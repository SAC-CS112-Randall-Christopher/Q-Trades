# CP18 source workflow and actual-model boundary

Issue [#28](https://github.com/SAC-CS112-Randall-Christopher/Q-Trades/issues/28)
requires evidence → supported model idea → deterministic result → independent
review → ordinary paper inbox → recorded comparison → supported follow-up.
This checkpoint extends the existing registry, controller and sole financial
writer. It does not confer incumbent qualification or economic value.

## Normal workflow in source

AI Lab → Local model research saves an immutable question, horizon and optional
preserved parent. A stable client request reconciles an unknown acknowledgment.
Current causal rule features, exact source hashes, executable-book observations,
permitted prior outcomes and offered rule capabilities are frozen by the server.
Changing a page timestamp is not a new question; changed actual bars can be.

A separately activated, qualified local policy permits one sequential model
call outside paper and registry locks. The model selects a supported semantic
capability or records missing data, redundancy or unsupported capability. It
cannot provide raw rule expressions, financial IDs, funding, risk or SQL.
The server issues exact breakout/range or preserved-parent lookback contracts.
Numerical coordination remains deterministic and has its own existing worker.

The existing prospective evaluator checks contiguous causal candles, horizon,
fresh book, rule support and policy. It does not manufacture a positive replay.
Its exact inputs are saved and reopened through the existing G: research tiers;
compact results carry their input hash/count and typed detail reference. Inputs
remain protected through the appropriate trial review horizon plus a day.

The required reviewer gets a fresh context containing the frozen method, matched
cost/policy and computed result. It receives no persuasive researcher transcript.
A negative or inconclusive review completes research without paper admission.
An allowed prospective review submits once through the ordinary inbox, which
rechecks current policy, parent, input availability, queue and financial capacity.
Only the existing financial controller reserves and funds the matched accounts.

The role releases model resources while the comparison is pending. A separately
authenticated read-only connection obtains the immutable scored event only when
available. Disclosure is recorded before the result enters follow-up context or
task detail. One subsequent answer references that exact event. Its explanation
is an annotation; it adds no P/L or financial permission. Existing outcomes remain
researchable if the current policy/parent later changes.

## Persistence, budgets and operation

Tasks, leases, attempts, questions and stable request identities use the existing
SQLite registry. Completed answers are saved before validation/dispatch and are
immutable. Unknown model completion never causes an automatic preferred-verdict
retry. The operator can authorize one separately recorded, budgeted transport
retry; a completed verdict cannot be retried that way. Lost proposal responses
reconcile the ordinary request ID before another local effect.

Eight active questions and 512 logical tasks bound retained metadata. Current
detail responses omit full candle inputs and have a 128-KiB bound. Independent
numerical work and ordinary paper management retain their separate loops.
Inference reserves its declared wall/token allowance before dispatch; the
controller's existing 30-second hourly contract is unchanged. Waits preserve
their dependencies and actual last-progress time rather than reporting a page
refresh as progress. Missing service, reviewer, storage, budget or queue capacity
blocks the particular stage while other eligible work can advance.

Role policy is absent/disabled by default. UI qualification, service state and
activation are separate. No UI route enables inference or changes the installed
policy. Current digest, template, server, prompt/schema contract, sampling,
context, CPU placement and supervision must match the qualification receipt.
The transport checks the operating paper health/resource guard before dispatch.
It addresses only the approved dedicated 11435 CPU runtime and never 11434/GIS.
