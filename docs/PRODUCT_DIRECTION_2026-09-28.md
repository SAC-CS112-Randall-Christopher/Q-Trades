Work from the existing Q-Trades application, not a new trading-bot scaffold. First read AGENTS.md, the current product direction, the dated analysis and affected code. Inspect the current branch, worktree, runtime and active qualification work before any change. The upload is a snapshot, not proof of the workstation's current state.

The product objective is credible net whole-account improvement after costs, with understandable evidence and bounded risk. Preserve paper-only operation, cash-only funding, all three longer-term tier objectives, project isolation and no arbitrary trade quotas. No live orders, borrowing, derivatives exposure, funding, automatic top-ups, risk escalation, paid inference, merge or deployment is authorized by this work. Return aspirations are not performance promises or reasons to alter evaluation standards.

Retain the existing deterministic engine, financial journal, market adapters, tested reservation logic, fixed breakout baselines and useful UI. Finish the existing crypto-learning plan rather than inventing a competing architecture. Keep the ledger authoritative. Research and LLM outputs may propose candidates; they may not change money or their own permissions.

Preserve legacy records and explicitly version any changed policy. Keep risk-reducing exits possible with adequate instrument data. Include the actual blocked reason and normal recovery action in the UI.

Reproduce the findings before fixing them. Add coverage for valuation loss between reservation and fill, missing held-symbol observations, later recovery without duplicate fills, risk-reducing exits during partial data loss, persistent drawdown stops across review/restart, idempotent operator recovery and atomic database rollback. Use disposable financial state and representative existing quote data; never inject synthetic trades into the running experiment. Do not add reinforcement learning, a large multi-agent system, new broker accounts or a live adapter at this stage.

For each step report the user outcome, exact changes, source/data versions, tests actually executed, cost/performance evidence, unresolved limitations and a draft PR when the repository exists. Preserve failed experiments, original fees, old policies and prior results. Do not change production behavior or stop active work merely by updating documents.
