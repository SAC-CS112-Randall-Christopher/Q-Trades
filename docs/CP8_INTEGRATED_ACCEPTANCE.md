# CP8 predeclared finite acceptance

The predeclared actual-host synthetic contract is scripts/verify_lab.py.SLOS: at four
shared executable BTC/ETH book ticks/second, transaction commit p95 <=100 ms, p99
<=250 ms, maximum <=2,000 ms; dispatch lag p99 <=250 ms and observed queue peak <=2;
parent RSS <=512 MiB with growth <=64 MiB; fixed research child RSS <=256 MiB;
parent CPU <=50% of one logical processor; final journal/projection reconciliation
balanced. No GPU calls and paid spending zero. CPU scopes and PostgreSQL storage
growth are reported separately. SLOs are declared before cases are observed.

Capacity uses 1/10/20 accounts, each with research idle and continuous fixed
synthetic fitting, thirty seconds and 120 ticks per case. The finite soak is exactly
twenty accounts with continuous fitting for **300 seconds / 1,200 ticks**, chosen
before its run. The script persists declaration/environment before sampling.
This exercises the actual PostgreSQL transaction, deterministic engine, shared
book path and bounded numerical worker on this host. It does not measure public
WebSocket latency, an elapsed multi-day account comparison, ArcGIS request latency
or 24/7 reliability. GPU use is excluded by the numerical path, not measured as
whole-host utilization of unrelated processes.

Integrated fault evidence uses generated disposable schemas/databases: exclusive
writer contention, committed-acknowledgment loss after actual child process exit,
restart/idempotent funding, uncommitted transaction rollback, pg_dump/pg_restore
with exact state/journal hashes, immutable journal constraints, stale/duplicate/
reordered data and clocks, observation disconnect/recovery, disk-pressure gates,
cancelled/stuck numerical work and optional-inference outage. Financial history is
never pruned by market retention. Pause-new-risk and manage-existing-risk remain
distinct; blocked exits and liquidation failures remain recorded rather than hidden.

Normal in-app acceptance traverses campaign setup/account inspection, experiment
queue/results, exploratory admission, matched controls, no-promotion/failures,
funding/control histories, pause/recovery and exports. Browser reload and database/
process restart are reported separately. Authentication requires local operator
header and same origin, trusted hosts and loopback startup. There is no remote
dashboard, signing route or live-order/funding API. Backup files contain only QA
data and remain ignored local artifacts.

The implementation receipt must record actual outcomes and failed checks, exact
source/environment, limits, durations and scopes. Synthetic software or resource
success never grants promotion or live authority. No running trial/model runtime,
updater, approved deployment, or production database is changed by this acceptance.
