# CP4 protected numerical research

One registered hypothesis goes through the normal experiment UI to a frozen result,
rejection or retained failure. The permanent SQLite registry is separate from the
financial PostgreSQL writer. Public inputs use the existing read-only snapshot.
The fixed numerical child receives only its research database and fenced lease;
it receives no venue client, financial connection, provider credentials or shell.
Arbitrary candidate code is not accepted. This is a capability restriction on the
registered runner, not a claim of an operating-system sandbox.

Plans include mechanism/falsification, feature/horizon, a chronological evaluation
window, input cutoff, and code/config/input hashes. Training-only preprocessing and
a horizon-sized purge remain authoritative. Test labels must have become available
before the frozen end. Immutable information windows conservatively protect all
features and instruments; hash changes do not grant fresh evidence. The previously
inspected period through 1790595239.9180105 is imported even without caller input.
The retained preflight's input/plan hashes reproduce exactly, including zero
positive-after-cost forecasts and its rejection. Reproduction is not new evidence.

Limits declared before acceptance: eight queued/active jobs, one numerical child,
25 seconds per attempt, at most two interrupted lease attempts, 12,000 input rows,
8 MiB per snapshot, 256 KiB per result, 512 retained jobs and a 512 MiB database cap.
Exhaustion blocks new work rather than deleting evidence. Worker cancellation,
timeout and lease failure retain consumed windows and attempt events. Source changes
block previously frozen work; no unrecorded refit replaces a failure. Paid budget
is zero and an LLM is not a prerequisite. Paper-health/resource constraints gate
research and never stop position management.

Validation: `tests/test_experiment_registry.py` exercises real retained preflight
reproduction, original rejection, omitted caller boundary, changed feature/hash,
concurrent reservations, exact retries, cancellation/restart, stale lease fencing,
input tampering, availability/revisions/gaps/purge, the real numerical child and
normal API authorization/export. Full-suite, source/build checks and browser
acceptance are recorded with each submitted checkpoint and final CP8 audit.

Initial development checks rejected accidentally future-dated QA plans; those
fixtures were corrected to declared synthetic historical times. An initial database
check failed while the dedicated QA PostgreSQL server was stopped; it was restarted
without touching the operating server. A shifted fixture correctly excluded the
last label whose availability was later than its declared end; its expected result
was corrected without weakening that boundary. The original preflight still
reproduces exactly. These development errors are distinct from final acceptance.

Quote-label forecast error is not an account return, independent samples or market
advantage. CP5 supplies distinct mechanisms and prospective adapters; CP6 adds
durable scheduling/budgets; CP7 adds forward evidence. No operating account, local
model, CP0 updater, deployment or live permissions change in CP4.
