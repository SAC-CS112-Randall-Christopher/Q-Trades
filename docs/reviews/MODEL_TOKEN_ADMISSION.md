# Model admission based on the actual token boundary

The human directs that unsupported estimates must not become admission blockers.
The PEFT transport previously rejected system plus packet JSON exceeding 32,768
UTF-8 bytes. That cutoff had no documented derivation from the tokenizer,
approved context or measured performance. It could refuse evidence before the
runner measured its actual token count.

Remove that byte cutoff. Preserve contract and retrieval compatibility, exact
model/profile/grant identity, attempt/allowance ownership, financial monitoring,
paper freshness, input eligibility, recording/storage, process ownership and
the existing resource owner. This source change does not authorize dispatch,
reset used attempts or reinterpret an earlier permission under changed guards.
An actual token refusal after dispatch retains its consumed attempt and failed
result; this repair does not authorize a refund or preferred-answer retry.

The existing runner applies the verified tokenizer's complete chat template,
including the system instructions and generation prompt. It permits input only
when input tokens plus the 1,024-token answer reserve fit the approved 8,192-token
profile; it rejects overflow before loading model weights. There is no silent
truncation. This is a configured operating envelope, not a claim that the
computer or model has an architectural maximum of 8,192 tokens. Its expansion
would require an actual matched resource/performance evaluation.

The next-method software fixture uses actual PEFT contract preflight. UTF-8 byte
sizes are diagnostic measurements, without a synthetic 9,000-byte admission
threshold or token-equivalent answer/template arithmetic. Matched metadata
reduction tests compare bytes and reconstruct complete financial outcomes; they
do not establish actual tokenizer fit or improved latency. Larger, valid packets
remain valid source inputs regardless of that old surrogate.

Boundary tests invoke the actual runner with a synthetic tokenizer and loader:
7,168 input tokens plus 1,024 answer tokens fit; one additional input token does
not. Overflow must prevent model loading and inference. Contract/retrieval
refusals and attempt state remain protected. These are software boundary tests,
not measurements of the installed tokenizer or computer's capacity.

Keep historical failures, including the earlier byte-guard refusals. A later
source repair cannot turn those runs green. No installed update/restart,
actual tokenizer/model/provider call, acquisition or research activation follows
from this source proposal.
