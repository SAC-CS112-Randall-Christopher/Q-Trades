capital**. Accounts offers Create, Start a finite run, Stop new entries and drain,
current progress, ordinary trade history and the permanent Journal. One run has

risk/uncertainty handling, accounting, exclusive writer and evidence recorder.

cooldown/hold timings do not change strategy-account rules. The account uses one
of the existing twenty managed/reserved slots. No automatic refund, reset or
second financial writer is introduced.

Financial history and full decision archives retain all diagnostic events and
state. Diagnostic account/event provenance labels identify random performance
activity; rankings, promotion, research-derived targets and automatic training
selection exclude it. Legitimate research targets remain available when their
complete original archive also contains diagnostic neighbors. Financial hashes,
event indices and commit links remain intact.

Operator requests preserve exact identities and settings across reloads and
unknown acknowledgments. Create can fund the account only once; an old Start or
Stop retry cannot create or stop a newer run. Confirmed 403/409/422 refusals retain
their reasons and release only the matching rejected intent. Unknown SQL/HTTP
outcomes remain unresolved until a bounded read through the existing owner
reopens the actual receipt. Stale inputs prevent new load while Stop remains
available. Stops drain through subsequent fresh executable books; uncertain
positions/orders are retained rather than inventing fills.

The new synchronous operator routes share the existing financial writer's
transaction lock through database scopes and cached-state publication. The
runtime retains each commit's own evidence receipt and work diagnostics. Work
policy observation/evaluation is serialized without changing the existing
100-ms advisory, >=500-ms/four-of-twenty blocker, one-second severe hold, recovery,
financial monitoring or storage protections. Sampled and complete evidence
packets retain the actual diagnostic admission Boolean for exact replay.
